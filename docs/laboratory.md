# 波形观察窗与仿真场景实验台

本功能扩展现有本机控制台，入口 `/laboratory`。沿用工业滑轨、金属框、三层字体和 Logo 字内金属流光。所有曲线都来自已保存的仿真输出；不连接物理设备，不把温度曲线称为现有健康评分的输入。

## 原始波形观察

选择当前控制台已登记的设备后，读取其已提交样本，显示振动波形（g）、温度趋势（°C）与振动幅度谱。可指定起始样本和读取点数，或观察最新一段。一次读取 2–4096 点，默认 2048 点；末尾不足时返回实际点数，缺失数据不补零。

`GET /api/waveform?run_id=...&device_id=...&count=2048&start_seq=0` 先核对控制台公开目录内的精确运行／设备组合，再通过现有查询网关检查当前权限和返回身份；凭据过期或授权撤销时不得继续读原始文件。`start_seq` 缺省表示最新已提交区间；只接收十进制非负整数参数。来源路径由服务器解析，浏览器不得指定文件路径。读取端核对身份、原始协议、SHA 和有界 NPZ 数组，不读取 `private_truth`。

持续采集以 `processed_samples` 为可读上界，避免显示尚未提交或尚无持久校验值的采集批次。离线实验以完整 Manifest 为依据。纳秒时间戳以十进制字符串传输，避免 JavaScript 浮点整数精度丢失；图表用相对时间轴。

频谱仅使用当前读取的真实振动样本尾部，至多 2046 点、1024 个频率分量，去均值并应用 Hann 窗和相干增益归一化。单位为 g 的单边幅度谱，不是功率谱密度或故障诊断结论。

## 独立参数实验

在启动服务时显式传入 `--laboratory-root <独立数据目录>` 才启用实验写入。不传此参数时，设备波形仍可读取，实验创建返回 `503 laboratory_unavailable`。

实验台提供正常、缓慢退化和突发故障三个预设。原六项创建请求继续兼容：`profile`、`seed`、`total_points`、`noise_std`、`degradation_rate_per_sample`、`fault_amplitude`。故障注入可同时增加 `fault_type`、`fault_start_seq`、`fault_duration_points`，选择既有 spike／step／burst 及发生位置和时长，详见[故障注入与工作台](workbench.md)。所有参数先校验，保存配置和随机种子，然后在独立运行目录执行既有仿真、消费和报告流程；不会修改当前持续采集的参数，也不把实验资源混入当前设备查询授权。

采样率固定 256 Hz，健康窗口 256 点；每次 8192–65536 点且为 256 的倍数。最多一个在途实验、20 条实验记录，独立实验目录预算 128 MiB。达到上限会返回明确错误，不自动删除旧实验来腾出配额。重启保留已完成实验，未完成记录标记为中断，不能显示为完成。

结果展示实际持久化健康窗口、告警、评分范围和报告摘要；`null` 或未评估保留原义。真值对账仅发生在既有报告层；波形读取、消费和评分不得读取故障真值。一次实验的检出结果不能代表独立保留集、整体 Gate0 或工业诊断能力。

## 本机接口

| 方法与路由 | 内容 |
| --- | --- |
| `GET /api/laboratory` | 启用状态、预设、限额和已保存实验列表 |
| `POST /api/laboratory/experiments` | 接收六个基础参数，或附三项故障注入参数，返回 `202` 与新实验状态 |
| `GET /api/laboratory/experiment?id=...` | 实验身份、参数、执行状态及真实结果 |
| `GET /api/laboratory/waveform?id=...&count=...&start_seq=...` | 读取服务拥有的已完成实验原始样本 |

所有接口沿用 loopback、Host、Origin、Fetch-Site 与严格参数校验。创建请求必须包含唯一同源 `Origin`、`X-G15-Console-Action: laboratory` 和 JSON 正文；不超过 4096 字节，拒绝重复键、未知字段、非有限值和不完整请求。成功接收不等于运行完成，页面轮询实际状态后显示结果。

页面切换来源时取消旧请求，避免把另一个设备或实验的波形画到当前选择上；加载、空数据、运行中、失败和过期状态分别显示。隐藏页面暂停自动轮询。温度与振动单位、窗口范围、样本点数和频谱算法保持可见。

## 验证范围

后端覆盖样本一致性、SHA／路径边界、有界解压、参数范围、异步状态、并发与磁盘限额、重启恢复和真实仿真分析；HTTP 覆盖公开目录约束、同源写入与错误传播。前端覆盖曲线数据、请求竞态、非有限值、失效状态与表单约束，浏览器验证实际设备和实验流程。测试运行目录始终在 Obsidian 笔记库之外。
