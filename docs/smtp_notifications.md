# 163 邮箱维护通知

控制台的“邮箱通知”使用自己的 163 邮箱发送维护建议与完整报告。手机用邮箱客户端收信，不需要打开运行平台的电脑地址。原来的 PushPlus 微信通知独立保留，两个渠道默认都关闭；配置邮箱不会自动启用微信渠道。

## 配置并确认一次实际收件

1. 本人在[网易 163 邮箱](https://mail.163.com/)登录发信账号，在客户端设置中开启 SMTP 服务并生成客户端授权码；按官网提示完成安全验证。平台需要客户端授权码，不填写网页登录密码。授权码只在本机控制台输入，不发送到聊天、Issue 或 PR。
2. 打开当前本机控制台的“邮箱通知”，填写完整的 `@163.com` 发信邮箱、一个收件邮箱、授权码、红色事件数和提醒间隔。收件邮箱可以与发信邮箱相同。保持自动提醒关闭，先保存设置。
3. 选择设备，点击预览，核对设备/运行、红色事件数、维护建议、报告时间以及两个附件的名称和大小。预览不发送，也不创建待发记录。
4. 点击一次发送测试。测试使用所选设备真实已提交的数据，会包含测试标记、维护建议、完整报告正文，以及 `summary.md`、`summary.json` 两个附件；不以本机链接代替报告。
5. 在手机邮箱确认收到，再检查建议、正文及两个附件。若暂未收到，先看平台的发送记录及邮箱垃圾箱，不重复点击；不确定结果可能仍在重试。完成收件确认后，再按需要启用自动提醒。

SMTP 返回接受只表示邮件服务器接收了提交，不证明进入收件箱或手机已显示。收件确认需要本人在手机核对。采集停止时测试仍可发送已提交的报告，页面须保留实际采集状态和报告时间；仿真报告不能写成真实硬件诊断或 Gate0 通过。

## 触发、队列与凭据变更

自动提醒按每个登记的 `run_id + device_id` 分别计算：本次运行累计红色告警边沿事件数达到配置阈值，而且相比已入队来源出现新红色事件时，冻结一份完整邮件。默认关闭，阈值 1 条、提醒间隔 600 秒。它不按异常窗口数或持续时间计数，不改变健康评分或红黄阈值。

邮箱使用独立的 `email-notifications.sqlite` 保存非秘密配置、来源游标与有界 outbox。来源游标和邮件快照在一个事务中提交。邮件在后台发送，不阻塞采集与分析。每封已入队邮件的发信人、收件人、正文、完整附件和 Message-ID 都固定；提醒间隔只延迟发送，不合并、覆盖旧邮件。

修改收件地址只影响后来创建的邮件，旧邮件仍发往原收件地址。修改发信地址不能把旧邮件改成由新账号发出：当前没有原发信账号凭据时，该任务明确失败。同一发信地址可以更新授权码，已排队邮件使用该账号当前有效的授权码。

授权码仅存于服务进程内存，不写入 SQLite、日志、报告、URL、静态资源或 API 响应；浏览器保存后清空输入框，不保存在 localStorage。设置请求省略授权码时，仅在发信地址未变的情况下保留现有值；传空字符串明确清除。更换发信地址时省略授权码会拒绝保存并保留原配置；若需要保存未配置的新地址，应关闭自动提醒并明确传空授权码。进程重启后需要重新填写授权码，持久任务仍保留，但未重新授权前不发送。

自动提醒关闭会暂停自动任务，显式测试仍可发送且不消耗自动去重游标。重试和进程恢复可能重复尝试同一封邮件；同一任务的 Message-ID 保持不变，不能承诺邮箱一定据此去重或严格只收到一次。默认最多尝试 3 次，重试间隔从 30 秒有界退避；发生 DATA 后断连等不确定结果时必须在记录中明确显示。

## 删除设置与清理待发邮件

在当前“163 邮箱”渠道点击“删除通知设置”，页面会先说明影响并要求再次确认。确认后清除本渠道保存的发件/收件地址和进程内授权码，恢复默认规则（关闭、1 条、600 秒），取消所有尚未尝试发送的任务；已发送和已失败的历史记录、来源去重游标及其他渠道保持。未保存的本渠道更改会一并丢弃。删除不需要重新输入授权码，删除后不能继续发送，重启也不会恢复已删除的邮箱设置。

若只需清理积压，先关闭并保存自动提醒，再点击“取消待发邮件”并确认。该操作只取消尚未尝试发送的自动邮件，保留收发件地址、授权码、提醒规则和历史记录，自动提醒继续关闭。未保存的表单更改也保留。已排队的显式测试、已尝试发送、正在重试或结果不确定的任务不会被当成未发送任务清掉。

取消采用终态记录：`state=failed` 且 `error_code=notification_cancelled`，页面显示“已取消 · 未发送”，尝试数仍为 0；正文、附件和原收件地址留作历史，不再派发。存在发送中、等待重试、已尝试待发或未闭合的渠道请求时，两种操作都返回 `409 notification_busy`，不进行部分清理；应先核对记录和收件结果，再重试。自动提醒仍开启时，取消待发返回 `409 notification_enabled`。

## HTTP 契约

读取接口支持 GET/HEAD，其他来源、请求体及参数边界继承[控制台契约](console.md)。邮箱设置、测试、删除与取消动作只开放下表所列 POST，要求唯一同源 Origin、`X-G15-Console-Action: notifications`、`application/json` 和唯一、非零、最多 4096 字节的 Content-Length。Transfer-Encoding、Expect、重复 JSON 键、未知键、重复参数及非法值均拒绝。

| 接口 | 内容 |
|---|---|
| `/api/email-notifications` | 返回非秘密设置、configured、监测状态与有界发送记录；授权码和消息正文不回显。`delivery_scope=smtp_accepted_not_handset_delivery`。 |
| `/api/email-notifications/preview?run_id=...&device_id=...` | 先经原真实查询 HTTP 授权和资源归属核对，再从完整快照生成 title、markdown、advice、red_count、报告时间及附件元数据。attachments 每项仅含 filename、content_type、bytes；不发送。 |
| POST `/api/email-notifications/settings` | 必填 enabled、threshold、cooldown_seconds、sender、recipient；可选 auth_code 和 channel。channel 仅允许 smtp163。 |
| POST `/api/email-notifications/test` | 仅接受 run_id、device_id；渠道已配置且任务成功持久入队后才返回 202。来源不可读、未授权、内容超限或 outbox 满均明确失败。 |
| POST `/api/email-notifications/settings/delete` | 仅接受空对象 `{}`；原子删除本渠道设置与凭据，返回安全状态、`deleted=true`、`cancelled_count`；不发送。 |
| POST `/api/email-notifications/pending/cancel` | 仅接受空对象 `{}`；须自动提醒已关闭，只取消未尝试的自动邮件，返回安全状态及 `cancelled_count`；配置保留，不发送。 |

`sender` 必须是一个 ASCII `@163.com` 邮箱；`recipient` 必须是一个 ASCII 邮箱。不接受显示名、多收件人、抄送、换行或自定义邮件头。阈值为 1..1000000 的整数，间隔为 0..86400 秒整数，均拒绝 bool。邮箱地址属于非秘密配置，会按上述用途持久保存；它们不需要提交到仓库或公开证据。

## 传输与完整性边界

生产连接固定为 `smtp.163.com:465`，从建连开始使用 TLS，校验证书链和主机名；平台不接受自定义 SMTP 主机、端口、关闭校验或明文降级参数。SMTP AUTH 使用发信邮箱与客户端授权码。[Python SMTP_SSL 文档](https://docs.python.org/3/library/smtplib.html#smtplib.SMTP_SSL)说明了从连接开始使用 TLS 的接口行为。

连接、TLS、认证和发送受绝对期限约束；每个 transport 最多一个在途请求 worker，DNS 超时后即使晚返回也不能继续登录或发送。已明确收到 DATA 接受确认后，关闭连接失败或超期不会变成重试；仍未闭合的请求会明确阻止服务宣称完成关闭。安全错误只暴露固定错误码，不回显服务商自由文本、收件人拒绝详情或授权码。

正文包含全部维护建议和完整报告；两个附件来自同一个快照。`summary.md` 的解码后字节等于该快照 Markdown 的 UTF-8 字节，包括原有换行；`summary.json` 为该快照 JSON 对象按 UTF-8、保留 Unicode、键排序且拒绝非有限值的完整序列化。消息超限时整封拒绝，不截断、拆掉附件或只发链接。

测试只使用合成账号、注入的假 SMTP 客户端或受控本地测试接收器；通过不能冒充网易真实接收，更不能冒充手机收件。真实邮件测试需要本人在本机配置授权码并在手机确认，不把授权码、真实邮箱、邮件原文或私人路径发布到公开仓库。

本功能不提供远程网页登录、设备动作、生产容量或独立验收结论。原 PushPlus 说明见[手机通知](notifications.md)。
