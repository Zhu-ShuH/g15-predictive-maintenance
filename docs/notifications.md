# 手机通知

在最新版控制台打开“手机通知”。先预览所选设备的建议和报告，核对内容，再配置自己的PushPlus令牌并保存；无需把令牌发送到聊天。启用后，后台会独立监测目录中的每台设备，网页关闭也不影响监测。

## 规则

每台设备在当前运行中累计的红色告警**事件数**达到阈值，且有未通知新事件时发送。默认阈值1条、最短间隔600秒、开关关闭。持续异常的多个窗口不是多条红色事件；黄色和浏览器分页重复记录均不补数。间隔内的新红色以完整快照耐久合并到待发任务，重启后仍可到期发送；设备和运行分别计数。已尝试、重试中或已接收的通知不可被合并改写。修改规则只影响后续触发，已入队任务保留原阈值与报告。

通知包含来源设备、累计数量、通用维护检查建议，以及同一已提交数据库快照生成的完整报告正文。建议需要人工确认，不执行设备控制。实时仿真报告保留verifiable=false及passed/detection_rate=null，不表示通过独立故障验收。

## 配置微信

1. 在自己的[PushPlus](https://www.pushplus.plus/)账号中取得令牌，并按其流程绑定接收微信。
2. 在本机通知页面的密码输入框填写，选择阈值与间隔，保存。令牌提交后清空、不回显，不进入localStorage或URL。
3. 点击“预览建议与报告”，确认设备与快照时间。
4. 点击“发送测试到微信”，再在手机上确认实际收到；未配置时按钮禁用。预览永不发送。
5. 勾选启用并保存后开始自动提醒。关闭开关会暂停自动任务。

策略与outbox保存在`--output-root`下的notifications.sqlite，令牌仅留在本次进程。重启前可在本机终端设置`G15_PUSHPLUS_TOKEN`，或重启后重新在页面填写；不得提交令牌到仓库。一个输出目录只运行一个通知发送进程。

## 状态与失败

“渠道已接收”只是PushPlus确认收到请求，不等同于手机送达；应以手机实际接收为准。官方[消息API](https://pushplus.plus/doc/guide/api.html)明确采用异步发送。未配置、暂停、采集停止、过期来源、待发送、重试、不确定结果及失败分别显示。

网络请求在独立发送线程中运行，不堵住采集和SQLite分析提交。失败有界重试；进程在渠道接收后、本地确认前中断时可能重复尝试，因此不承诺严格仅一次送达。完整报告过大时明确报错，绝不只发本机127.0.0.1链接或悄悄截断正文。通知记录仅显示非敏感元数据。

此功能是本机仿真平台增量，不增加远程登录、短信付费通道、真实硬件诊断或设备动作。手机实送需要用户自己的有效令牌与外部渠道可用，本地测试接收器通过不能冒充真实手机送达。
