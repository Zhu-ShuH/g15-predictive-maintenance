# ADR-0008：高风险操作使用应用级只增审计链

- 状态：已由 PR #147 合入（`300f26d1`），Issue #143 已关闭，C4 非作者复核通过；应用级只增已实现，文件级防篡改不声称
- 日期：2026-11-10
- 关联：Issue #143、Issue #127、期末项目行业红线

## 背景

`reset-alarms` 会显式清空一条告警 streak。#147 合入前的实现把 `reset_event` 与
`reset_history` 放在可更新的 `alarm_states.state_json` 中，能保留业务恢复上下文，
但不能满足“审计日志只增不改”：同一行仍由正常窗口写入反复 UPDATE，拥有普通写
连接的代码也可以覆盖整段 JSON。

本项目没有真实设备执行器，reset 也不会删除历史告警或触发停机；但它仍是需要
操作者 `--yes` 和原因的高风险软件操作，应留下独立且可验证的只增记录。

## 决策

在同一个 `results.sqlite` 中增加 `audit_events`，首个覆盖动作是
`alarm_state.reset`。每次 reset 在同一 `BEGIN IMMEDIATE` 事务中完成：

1. 读取并归档旧状态；
2. 更新 `alarm_states`；
3. INSERT 一条审计事件；
4. 一并 COMMIT，任一失败全部回滚。

审计表字段为：

| 字段 | 语义 |
|---|---|
| `event_sequence` | 数据库内严格递增序号，也是主键 |
| `event_time_utc` | 与 reset 使用同一 RFC3339 UTC 时刻 |
| `action` | 当前为 `alarm_state.reset` |
| `run_id/device_id/rule_id` | 被操作对象的稳定范围 |
| `actor_ref` | 脱敏来源标识；本地 CLI 首版为 `local-cli`，不伪造个人身份 |
| `reason` | 操作者提交的非空理由；不得放 token、密码或个人敏感信息 |
| `payload_json` | 规范化最小证据，不保存 `private_truth` 或完整旧状态原文 |
| `previous_hash` | 前一条事件哈希；首条为 `NULL` |
| `event_hash` | 当前事件规范化内容与 `previous_hash` 的 SHA-256 |

`payload_json` 记录旧状态文本的 SHA-256、版本、能否严格解码、锚点及此前 reset
数量。旧状态原文继续由兼容信封保留；审计表不复制整段原文，以减小敏感数据和
无界增长风险。

数据库建立三个触发器：`BEFORE UPDATE` / `BEFORE DELETE` 拒绝改删，
`BEFORE INSERT` 只接受“当前最大序号 + 1”且 `previous_hash` 等于当前尾哈希的
新事件，并显式拒绝复用已有 `event_hash`。因此普通写连接不能借 SQLite
`INSERT OR REPLACE`、复用序号、跳号或错误前驱改写历史；违规均以
`RAISE(ABORT, 'audit_events is append-only')` 失败。仓库提供
`verify_audit_chain()`，逐行重新规范化并验证序号、前驱与哈希；成功返回已校验
事件数，失败抛 `AuditChainError`，不能把断链当成空审计。

## 威胁边界

这是**应用级只增 + 有限篡改可检**，不是密码学意义的不可篡改存储。拥有数据库
文件、DDL 或操作系统管理员权限的人可以删除触发器、替换整个文件，甚至重算完整
哈希链。由于首版没有独立保存的尾哈希锚点，管理员删除最后一条事件或整段尾缀后，
剩余前缀仍可能通过链校验；这一类尾部截断不可检。现场陈述必须保留这个边界。若
未来接真实设备或进入生产环境，应把尾锚与审计复制到独立 WORM/远端签名存储，
并由不同权限域保管密钥。

同样，`actor_ref=local-cli` 只证明动作来源于当前本地入口，不证明自然人身份。
#135 的认证只读查询入口已由 #149 合入，但没有开放管理/reset 端点，也未改变本地
reset 的 actor 语义。未来若增加管理入口，应在不记录 token 的前提下传入脱敏 actor
标识，并另行评审权限、吊销和日志策略。

## 被否决方案

1. **继续只用 `state_json.reset_history`**：兼容业务恢复，但整行可变，不满足红线。
2. **仅追加 JSONL 文件**：很难与 SQLite 状态更新原子提交；崩溃可能只写一边。
3. **独立 `audit.sqlite`**：跨 WAL 数据库事务的原子性边界更复杂，首版不采用。
4. **把原状态全文写入审计表**：证据重复、增长无界，并扩大敏感内容暴露面。
5. **宣称触发器使日志不可篡改**：超出真实威胁模型，明确禁止。

## 后果与迁移

- 新数据库初始化时自动创建审计表、索引和不可改删触发器；重复初始化幂等。
- 所有 reset/消费写入口先幂等初始化；旧数据库下次写入时增加空表和三个触发器，
  不回填历史 reset，避免伪造不存在的原始时间和操作者证据；历史仍按旧信封展示，
  并标为迁移前记录。
- `AlarmResetResult` 和 CLI 输出审计序号、前驱哈希与事件哈希，方便现场固定证据。
- 正常消费不会写审计表；只有真实高风险动作才追加，避免重放制造重复审计。
- 数据库备份/恢复必须连同 `audit_events`、触发器和链校验结果一起验证。

## 验证

- 单次与连续 reset 形成 `1 → 2 → ...` 哈希链；
- UPDATE/DELETE/INSERT OR REPLACE、跳号和错误前驱被触发器拒绝；
- 旧库缺少审计表时，首次 reset 幂等迁移后再原子追加；
- 模拟有 DDL 权限者绕过触发器改 payload 后，链校验失败；
- 强制审计 INSERT 失败时，状态 UPDATE 同事务回滚；
- reset 后继续消费和重开数据库不删除审计；
- CLI 输出稳定审计引用，但不输出旧状态原文、token 或 `private_truth`。
