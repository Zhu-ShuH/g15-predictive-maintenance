## 问题

PR #15 在 engine.py 内定义 SimulationChunk，并使用按绝对索引寻址的噪声，rng 参数允许省略且不参与生成。接口草案只写出签名，尚未完整规定参数可选性、随机流行为和公共数据类位置。

## 建议

1. SimulationChunk 最终由 common/types.py 统一定义，B1/C1/C4/C2 使用同一类型。C3 管生产与消费配置，B2 提案特征、评分和告警状态结构；跨模块字段由 A/C4 统一审查。
2. 保留按 seed、设备/机制、绝对索引确定数据的设计方向；固定算法版本、依赖和内部块网格后验证任意分片组合得到相同数据。内部块大小不能悄然改变后仍宣称同版本逐点一致。
3. 兼容保留 rng 时明确“不消耗传入生成器状态”；是否改成可选参数需要同步接口文档和调用测试，不能称签名完全未变。测试保存调用前后状态比较，禁止 assert … or True。
   - 2026-10-18 决议：PR #31 已合入 main（`e8e29248`），`SimulationChunk` 统一到 `common/types.py`；`simulate_chunk` 保留可选 `rng` 且不消费调用方状态。公共契约、兼容 import 与状态回归测试见该 PR；上句的可选性待决事项据此收口，不扩大为所有配置类型的迁移。
4. 不静默钳位有限负值：振动字段先按有符号测量解释，温度按 degC；若改成幅值/能量等非负量，由 B2/C3 提议并同步单位及规则。

## 实施与放行

单独的共享类型任务列出 common/types.py、受影响 import 和测试，由 A/B1/C4 协作；不要趁 #2 文档 PR 夹带代码迁移。迁移前不让 C4 复制第二个同名类型。评审须明确每个字段、shape、dtype、空块与校验责任；合并后检查分片一致性、错误输入、RNG 状态和序列化对接。
