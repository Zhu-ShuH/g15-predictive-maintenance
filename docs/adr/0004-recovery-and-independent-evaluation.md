# ADR-0004：告警状态恢复与独立验收

- 状态：提案，待 B2/C2/C1/C4/C5 反馈及 A 审核；2026-10-16；Issue #2。

## 建议

消费每个分片时，把窗口、健康分、告警、最后处理序号、连续异常计数、当前级别与恢复进度和分片完成游标在同一 SQLite 事务提交。alarm_states 为待评审候选，state_json 需有显式版本；主键建议按 run/device/rule。重启只从已提交状态恢复，不依赖丢失的全局变量。

仿真故障区间使用 [start_seq, end_seq_exclusive)，跨片同 event_id 在真值中只出现一次。事件重叠可选加性叠加或禁止，须由 C1/B1/C5 先用数值样例确认后再冻结；本提案不替他们虚构决定。

验证器独立匹配告警与真值，一个告警不能重复匹配多个注入事件；检测窗口和允许延迟必须测试前固定。零事件的检出率用 null，正常场景另报误报。消费者只看公开测量与规则，真值路径不进入检测接口。

## 验证

C2/B2 验证跨片状态与事务，C5 用相同输入比较不中断、中断重启、重复重放的最终结果；至少演示业务故障、文件损坏和消费进程终止三类场景。进程强杀不等于真实断电，不能据此宣称断电零丢失。
