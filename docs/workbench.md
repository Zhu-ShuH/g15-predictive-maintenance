# 故障注入、回放与运行对比

本机仿真控制台新增 `/workbench`，侧边栏进入分析工作台。故障注入入口仍在 `/laboratory` 的独立实验中；其余操作共用工作台的运行目录。保留工业滑轨、金属组件框、三层字形与 Logo 字内金属流光，不增加运行时外部资源或第三方依赖。

## 故障注入

独立实验的“突发故障”支持既有 `spike`（尖峰）、`step`（阶跃）、`burst`（突发振荡）三种类型。发生时刻与持续时间由 256 Hz 换算为整数样本点，非采样网格时间不静默舍入；强度是原仿真器振动幅度参数，范围 0–10 g。可同时配置噪声、种子与样本量，运行后查看实际波形、健康分和告警。

创建接口兼容原六参数请求；扩展故障请求同时增加 `fault_type`、`fault_start_seq`、`fault_duration_points`。扩展字段只用于 `profile=sudden_fault`。起点非负、持续点数至少 1（burst 至少 3），终点不得超过总点数，不要求健康窗口对齐。旧六参数故障仍采用 spike、总点数中间向下对齐 256 点的起点、512 点时长。历史参数不被新表单覆盖，载入参数不自动创建运行。

## 历史回放

选择当前设备、已保存独立实验或已结束采集会话，拖动时间轴查看对应的实际健康窗口与原始波形。告警与维护建议按回放位置显示，不能把未来告警提前带入历史。维护建议沿用既有规则映射，属于事件检查建议，不宣称已确认零部件故障或已执行维修。

窗口来自同一已提交 SQLite 快照。原始样本继续通过摘要核验读取；读数缺失不补零，读取失败不伪装为健康。每次完整读取至多 8192 个健康窗口、4096 条告警；超过上限明确返回 413，不将截断结果称为全程。

持续服务在启动时从显式配置的 `--output-root` 注册最近至多 64 个结束会话、1000 个历史资源。只接受服务保存的 catalog、capture-config、session-status 与 live-session 身份一致的记录；活动会话、路径链接、无效配置或不完整身份不进入历史目录。当前设备读取仍逐次验证真实上游权限；历史访问是本机用户对已保存会话的独立资源授权，不延长旧会话 token。浏览器不能传入目录或文件路径。

## 多设备与运行对比

最多选择 4 个运行并排比较健康趋势、告警次数、评分规则、配置及处理时间。曲线按“从本次运行开始的样本时间”对齐，保留各自采样率和实际持续范围；不同长度的运行不补齐假数据。

实时或归档设备的处理延迟来自样本生成开始至 SQLite 提交返回的实际观测，显示全程均值、最大值及观测数量。独立实验显示实际生成、分析、报告总耗时，两者分别标注，不混作同一性能指标；未记录返回 null，不显示为零延迟。

## 告警处置

选中真实告警后，可确认告警或追加处理备注。要求填写处理人和备注；处理人是本机用户自填的记录身份，不代表已认证的独立账户。确认仅表示已阅和记录，不清除分析系统的活动告警，不改健康分，不执行设备动作。

记录写入独立 `dispositions.sqlite`，保存原运行、设备、告警、规则、样本位置、动作、处理人、备注、UTC 时间和顺序。数据库触发器拒绝更新、删除，记录形成摘要链，启动时核验；这用于本机追溯，不等同于外部签名或不可抵赖存证。幂等请求标识防止同一次提交因网络重试重复写入；同一告警重复确认返回冲突，之后仍可追加备注。重启保留记录，分析结果数据库始终只读。

处理人上限 80 字符、备注 2000 字符，最多 10000 条记录，记录库大小有界。超限返回明确错误，不自动删除旧记录。前端以文本显示备注，导出对 HTML 和 CSV 进行相应转义。

## 比较报告导出

报告使用本次读取的实际比较快照，保留生成时间、源运行、配置、评分规则、指标及时间口径。可导出结构化 JSON、CSV 摘要及含 SVG 趋势图与摘要的独立 HTML 报告。导出不重新计算健康评分，也不把某次受控场景结果当作整体检出率或真实工业诊断结论。

## 本机 API

| 路由 | 内容 |
| --- | --- |
| `GET /api/workbench` | 可选运行、来源类型、状态与限额 |
| `GET /api/workbench/run?id=...` | 完整有界健康窗口、告警、事件建议、配置、时间统计及处置记录 |
| `GET /api/workbench/waveform?id=...&start_seq=...&count=...` | 同一资源的已提交原始波形，复用 2–4096 点限制和共享并发限制 |
| `GET /api/workbench/compare?ids=...` | 逗号分隔的 1–4 个唯一资源，按相对秒对齐的比较快照 |
| `GET /api/workbench/dispositions?id=...` | 获授权运行的处置轨迹 |
| `POST /api/workbench/dispositions` | 严格字段 `id,alarm_key,action,operator,note,request_id`；action 为 acknowledge 或 note |

资源标识为 `live:<run_id>` 或 `experiment:<lab_id>`，仅用于服务端目录匹配。处置 POST 要求唯一同源 Origin、`X-G15-Console-Action: workbench` 和 JSON，正文上限 16384 字节；其他既有 POST 上限保持 4096 字节。拒绝重复键、未知字段、非有限数、额外参数及跨源写入。空数据、来源丢失、授权失效、超限、重复确认和请求冲突分别返回明确状态。

`g15.live` 自动启用本机工作台，处置库默认置于 `<output-root>/workbench`，可用 `--operations-root` 显式指定。独立实验仍须 `--laboratory-root` 启用；未传实验根时，工作台仍可回放当前与归档采集数据。独立 `g15.console` 可由调用方传入 `operations_provider`，未配置时工作台接口返回 503。

## 验证与验收边界

测试覆盖三种真实故障生成、参数与旧历史兼容、回放数据一致性、当前权限校验、归档注册、路径及大小限制、并发幂等、处置持久化与分析库不被修改，以及真实 HTTP/CLI。前端覆盖时间轴过滤、请求竞态、比较及导出转义，并进行桌面和窄屏浏览器验证。

本次是用户直接授权的本地功能扩展；用户整体体验验收、正式接口评审、PR 合并和两种 Linux 验证分别保留其独立状态，不因本地测试通过自动完成。
