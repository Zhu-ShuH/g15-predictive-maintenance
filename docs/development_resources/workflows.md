## J1：实现一个模块并给出可信测试

适用：所有模块实现者；参考 R06/R07，S03 可选。

```text
按我已说明的角色和当前 Issue 工作。先核对真实分支、现有源码和本次允许修改的路径；测试新文件也必须在 Issue 范围内。
只实现本次需求，从输入、输出、边界和失败行为设计小样例；预期值来自手算、独立参考或明确契约，不能复制实现的同一计算生成 expected。
优先测试正常、空输入、非法输入、边界和重复执行中与该模块有关的情形；不要机械地为每个函数凑数量。
断言必须真的会失败，禁止 or True；未实现功能不能用无条件 skip/xfail 掩盖。第三方示例里的演示失败用例不能原样当验收。
在 pp03 中执行适用检查并记录命令、退出码、关键输出；未运行写原因。修改范围外的问题只提出具体依赖，不代改其他组员模块。
最后列出：Issue与完成内容、变更文件、真实测试证据、未解决依赖/风险、PR标题与下一步。
```

完成标志：相关行为有可解释的预期和真实结果，未伪称业务闭环已完成。

## J2：随机流、NPZ 与跨分片契约

适用：B1/C1/C4；参考 R03/R04/R07；公共类型和 RNG 决策跟踪 #17。

```text
按当前 Issue 只处理自己的仿真、故障或生产模块。先列出依赖的已评审类型、字段、单位、函数签名与 rng 行为；未评审处明确列为依赖，不另造兼容类型。
随机性按项目的绝对采样序号、seed 与稳定子流方案验证；NumPy 子流机制只是参考，不假定改分片方式后自然逐点相同。调用者 rng 是否消费、是否保持状态必须遵守最终契约，不能用恒真断言跳过验证。
生产和序列化分别验证双信号、seq、timestamp_ns 的长度与 dtype、尾分片、跨片连续性、相同配置复现、非法数值失败。NPZ 使用 allow_pickle=False；原子文件更名、SHA 与 complete Manifest 必须有对应证据，失败不能发布完成标志。
分别记录算法内核耗时与完整生产耗时；只有后者且满足 docs/acceptance.md 的起止范围才可用于百万点验收。性能结果必须含配置、提交与环境。
只补本 Issue 获准测试；跨角色需要的联调测试交 C5 或先由 A 扩大任务范围。
```

完成标志：数值复现与文件契约可核对；不把内核快、能读 NPZ 或子流独立当成全部生产验收。

## J3：SQLite 事务、幂等与恢复

适用：C2，B2/C5 协作；参考 R08/R07。

```text
先读项目数据库契约和 B2/C2 对告警状态的评审结论，再处理当前 Issue。Python sqlite3 参考固定 3.12 文档，不使用仅上游主分支存在的新接口。
为每例使用独立临时 SQLite 文件。验证实际事务：特征、评分、告警、告警状态和 processed_chunks 同一事务提交；失败时整体回滚；同一分片重复消费不增加重复行；同名分片 SHA 改变必须拒绝。
用不中断的基准运行与中断重启运行比对窗口、评分、告警、持久状态；不只比较总行数。真实 kill -9 在 Linux 执行，Windows 结果不能代替它，也不能把 Python 异常回滚称为强杀测试。
不要 mock 掉本次正在验证的数据库提交。状态字段未评审或功能尚缺时如实说明，不能只靠内存状态宣布恢复完成。
```

完成标志：有实际 SQLite 行为与恢复对照证据，未把连接成功当作幂等通过。

## J4：独立故障评估与报告

适用：C5；B2 提供固定规则；参考 R02/R06。

```text
以 docs/acceptance.md 为唯一验收数值来源。先记录配置和规则摘要、代码提交、开发与验证 seed；验证 seed 不用于调参。未取得 B2 的固定规则时先实现独立指标小样例，不编造端到端成绩。
消费者/analysis 不读取真值；只有验证器把独立预测与 faults.json 对账。按项目半开事件区间、允许告警窗口、device_id 和一对一匹配计算；不要直接照搬 NAB 的归一化分数。
至少用人工构造的真值和告警验证：全部命中、漏掉一个、额外误报、一条告警覆盖两个事件、边界落点、重复告警、零事件。零事件召回率为 null，正常场景有告警就是误报。
按固定受控集执行时报告逐事件匹配、TP/FN/FP、重复/未匹配告警、延迟与真实错误；保留失败结果，不改门槛使其变绿。报告 JSON 与 Markdown 保持同口径。
```

完成标志：指标小样例和实际业务结果分开记录，100% 结论只适用于已执行的受控集。

## J6：处理 PR 失败与审查意见

适用：A 与 PR 作者；参考 S01/S02。

```text
先确认目标仓库、PR、最新 head SHA、失败检查或尚未解决的审查意见，再处理已授权的具体问题。已有批准若对应旧提交，不当成新提交已获批准。
用可用的 GitHub 连接读取日志与线程；gh CLI 没有安装/认证时可用现有连接或准确报告限制，不擅自安装整套工具或输出凭据。
定位失败的根因，按当前 Issue 做最小改动，记录改动与实际验证。只重跑能回答具体风险的检查，不删除测试、降低质量门槛或扩大到其他角色模块。
只有用户授权回复相关 PR 时才发布回复；回复列出修复提交与证据，不能替审查人点 Approve、伪造人工结论或绕过分支保护。推送后核对当前提交的真实 CI 状态。
```

完成标志：每个已授权问题有对应修复与证据，剩余依赖有明确责任人。
