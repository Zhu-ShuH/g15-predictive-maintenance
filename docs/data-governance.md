# G15 数据治理与安全边界

> 状态：期末验收基线；适用于教学仿真、演示证据和未来查询服务。
> 本文给出项目规则，不代表已经通过教师现场检查或外部合规认证。

## 1. 适用范围与默认边界

G15 是本地运行的预测性维护教学沙盘。当前主链读取仓库内 YAML，生成
NPZ/Manifest、SQLite 和 JSON/Markdown 报告；运行时不依赖云服务、模型 API
或真实设备网络。项目只产生仿真数据，不接入 PLC、传感器、执行器，也不发出
停机或维修控制指令。

默认策略是“数据不出域”：`runs/` 仅保存在执行机器的受控目录，不提交 Git，
不自动上传。若教师需要复制验收证据，只导出经过下述审批和脱敏的最小集合。

## 2. 数据分级

| 级别 | 数据 | 默认处置 |
|---|---|---|
| P0 公开 | 源码、公开配置、接口与空白模板 | 可进入公开仓库；仍需审查路径、账号和许可证 |
| P1 项目内部 | 仿真原始分片、SQLite、性能原始日志、机器规格 | 留在项目域；外发前最小化、脱敏并审批 |
| P2 受限 | `private_truth/`、逐请求审计、权限映射、失败转储 | 仅授权角色读取；不得进入普通查询响应或公开演示包 |
| P3 禁止入库 | token、密码、私钥、真实个人身份、真实厂区数据 | 不得写入仓库、配置、日志或测试夹具 |

`private_truth` 的“受限”是应用契约，不等同于操作系统访问控制。消费者、分析、
`reporting.verifier` 和未来查询服务不得读取该目录；只有报告层在真值对账时读取。

## 3. 凭据和密码红线

当前系统不提供密码登录，也不持久化密码，因此“密码哈希”对当前实现为不适用，
不能为了展示合规而增加一个无业务用途的账号库。未来查询服务的 bearer secret
必须在运行时注入，仓库和 YAML 只允许保存不可逆校验材料或占位说明；token、
secret 和认证头不得进入日志、报告、异常文本或测试快照。

如果以后正式引入口令认证，必须先走 ADR 和接口评审，并至少满足：

1. 使用 PBKDF2-HMAC、scrypt、bcrypt 或 Argon2 等口令派生算法；每个口令使用
   独立随机盐和评审后的工作因子；禁止裸 SHA-256/MD5。
2. 使用恒定时间比较；只保存算法、参数、盐和派生值，不保存可逆密文或明文。
3. 提供升级工作因子、吊销、失败限速和秘密轮换方案。
4. 单元测试只使用测试秘密，任何示例均不得成为默认生产凭据。

## 4. 脱敏与外发审批

外发前由数据所有者准备清单，A 与一名非作者复核者共同批准。最少填写：

```text
申请编号：
用途与接收方：
数据文件及 SHA-256：
字段和分级：
脱敏/聚合方法：
保留期限与删除方式：
数据所有者批准：
非作者复核：
导出时间、操作者与结果：
```

脱敏要求：

- 移除 token、认证头、真实姓名、邮箱、主机用户名和绝对个人路径；
- `run_id`、`device_id`、`actor_ref` 只保留完成验收所需的稳定假名；
- 性能证据优先给出聚合分布，原始逐请求日志只在受控域留存；
- 不把哈希值误称为匿名化；低基数字段仍可能被重识别；
- `private_truth` 仅在证明报告对账时按最小范围导出，不进入业务查询样例；
- 导出后重新扫描秘密和个人标识，并记录导出包 SHA-256。

未经批准的数据不得通过网盘、聊天附件、公开 Issue/PR、邮件或第三方分析平台
外发。审批表可以留空模板入库，真实审批记录若含敏感信息应留在受控证据域。

## 5. 审计边界

`reset-alarms` 已要求显式 `--yes` 和非空原因，但当前历史仍位于可更新的状态
信封中，不能据此宣称满足“append-only”。独立只增审计和防 UPDATE/DELETE
约束由 Issue #143 交付；在其合入并实测前，本项状态为**未满足**。

任何审计记录都不得包含密码、token、认证头、真实个人身份或 `private_truth`
原文。应用级只增和哈希链也不能抵抗拥有数据库文件或 DDL 权限的管理员，答辩
中必须陈述该威胁边界。

## 6. 真实设备与误停安全

当前项目是只读分析与告警沙盘，没有设备控制通道；“真实设备变更”和“误停”
对当前实现为不适用。该不适用结论不是未来接入的豁免。若要接入真实设备，必须
在编码前同时具备：

1. 已批准的变更单、精确设备/点位清单、维护窗口和回退方案；
2. 默认旁路或只读接入，不改变控制回路；
3. 数据所有者与安全/模块负责人两名人员复核；
4. 告警到停机之间的人工确认位，禁止自动执行停机；
5. 独立测试环境、最小权限、断网/超时降级和紧急旁路；
6. 操作前后审计、结果核对和事故复盘。

`reset-alarms` 只重置软件告警 streak，不删除历史告警、不重新分析 run，也不
控制设备。缺少 `--yes` 时必须失败，不能由消费失败或恢复脚本隐式触发。

## 7. 现场核查清单

- [ ] `git status` 不含 `runs/`、秘密、真实数据或个人路径。
- [ ] 在禁网状态下，已安装环境仍可完成 `demo.sh` 与 `verify.sh`；保留命令和退出码。
- [ ] 日志扫描未发现 token、认证头、密码、个人身份或 `private_truth` 原文。
- [ ] 外发包有审批记录、脱敏说明和 SHA-256。
- [ ] `reset-alarms` 无 `--yes` 会拒绝，成功操作有原因和审计证据。
- [ ] Issue #143 的 UPDATE/DELETE 拒绝及哈希链测试已在候选 SHA 实跑；未合入时标未满足。
- [ ] 答辩明确“只告警、不控制设备”，不把仿真结果外推为真实工业准确率。
